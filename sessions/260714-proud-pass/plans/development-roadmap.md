## 🎯 P0：核心交互增强（最高优先级）

### P0-1：提示词优化按钮

**目标**：帮助用户将模糊请求转化为清晰、结构化的指令

**核心价值**：
- 降低用户提示词编写门槛
- 提升 AI 理解准确率
- 减少多轮澄清对话

**实现概要**：
- 输入框工具栏新增优化按钮（✨ 图标）
- 调用轻量模型（DeepSeek Flash / Qwen Flash）优化当前输入
- 直接替换输入框内容 + 5 秒撤回机制
- 分层扩展策略：极短输入大胆扩展、中等输入结构化优化、详细输入轻量微调
- 区分 Chat/Agent 模式的优化重点

**技术栈**：
- 前端：TipTap Editor API、React Hook
- 后端：IPC Handler、Model Manager
- 新增文件：`optimize-prompt.ts`（系统指令模板）
- 修改文件：7 个

**详细规格**：[P0-1-prompt-optimization-spec.md](./P0-1-prompt-optimization-spec.md)

**工时估算**：
- Phase 1（核心功能）：1-2 周
- Phase 2（集成测试）：1 周
- Phase 3（体验优化）：1 周
- **总计：3-4 周**

---

### P0-2：意图确认/结构化选项

**目标**：让 Agent 在首轮交互中主动识别模糊意图，通过结构化选项确认用户真实需求

**核心价值**：
- 避免 Agent 错误执行模糊请求
- 减少返工和时间浪费
- 提升用户信任度

**实现概要**：
- 系统提示词增强：新增"意图确认与结构化选项"规则段落
- 复用现有 `AskUserQuestion` 工具和 `AskUserBanner` UI
- 零额外 API 调用，完全基于系统提示词引导 Agent 行为
- 区分"关键决策"（必须确认）和"低风险细节"（自行判断）
- 避免过度确认：同一轮最多 3 个问题

**技术栈**：
- 仅修改：`agent-prompt-builder.ts`（1 个文件）
- 替换段落："不确定性处理" → "意图确认与结构化选项"

**详细规格**：[P0-2-intent-confirmation-spec.md](./P0-2-intent-confirmation-spec.md)

**工时估算**：
- Phase 1（提示词修改）：0.5 天
- Phase 2（提示词验证）：0.5 天
- Phase 3（行为验证）：1 天
- Phase 4（回归测试）：0.5 天
- **总计：2-3 天**

## 📈 P1：信息展示增强

### P1-1：证据面板（Evidence Panel）

**目标**：在对话侧边栏展示 Agent 的推理过程、参考来源和决策依据

**核心价值**：
- 提升 Agent 决策透明度
- 帮助用户理解 Agent 的思考过程
- 便于用户验证和纠正 Agent 的判断

**待调研内容**：
- 竞品（QoderWork、WorkBuddy）的证据面板设计
- 需要展示哪些类型的证据（文件引用、搜索结果、推理链、置信度）
- UI 交互方式（侧边栏、弹窗、内联）
- 与现有对话流的整合方式

**预估工时**：5-7 天（待详细规划后确认）

**依赖**：无硬性依赖，但建议在 P0 完成后实施

---

## ⏰ P2：自动化与交互增强

### P2-1：定时任务系统

**目标**：支持用户创建定时执行的自动化任务（如每日代码审查、每周报告生成）

**核心价值**：
- 实现无人值守的自动化工作流
- 支持定期监控和检查
- 提升重复性任务的效率

**待调研内容**：
- 现有 `automation` Skill 的能力和限制
- Cron 表达式的用户友好性
- 任务执行的触发机制和通知方式
- 任务结果的持久化和查看方式

**预估工时**：7-10 天（待详细规划后确认）

**依赖**：建议在 P0 完成后实施，确保基础交互稳定

---

### P2-2：语音交互增强

**目标**：增强语音输入/输出能力，支持自然语言对话

**核心价值**：
- 提供更自然的交互方式
- 支持多任务场景（如边走边用）
- 降低输入门槛

**待调研内容**：
- 现有 `SpeechButton` 的能力
- 语音识别的准确率和延迟
- TTS（文本转语音）的自然度
- 语音命令的识别和解析

**预估工时**：5-7 天（待详细规划后确认）

**依赖**：无硬性依赖，可与 P0 并行开发

---

## 🎨 P3：高级功能

### P3-1：专家套件/角色模板

**目标**：提供预设的专家角色模板（如代码审查员、产品经理、数据分析师）

**核心价值**：
- 快速切换到特定领域的专家视角
- 提供领域特定的最佳实践
- 降低复杂任务的入门门槛

**降优先级原因**：
- 用户可以通过自定义系统提示词实现类似效果
- 与 P0-1（提示词优化）功能有重叠
- 需要大量领域知识沉淀

**待调研内容**：
- 需要哪些专家角色
- 每个角色的系统提示词设计
- 角色切换的 UI 交互
- 与现有 Skill 系统的整合

**预估工时**：3-5 天（待详细规划后确认）

**依赖**：建议在 P1（证据面板）完成后实施，确保基础信息展示完善

## ⚠️ 风险与缓解

### 技术风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 轻量模型优化质量不稳定 | 中 | 高 | 提供撤回机制 + 用户反馈通道 |
| 系统提示词规则被模型忽略 | 中 | 中 | 使用具体示例强化指令 + 定期回归测试 |
| 证据面板性能问题 | 低 | 中 | 懒加载 + 分页 + 缓存策略 |
| 定时任务执行失败 | 中 | 高 | 重试机制 + 错误通知 + 执行日志 |

### 产品风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| 过度确认导致用户厌烦 | 低 | 中 | 明确"不需要确认"场景 + A/B 测试 |
| 提示词优化偏离用户意图 | 中 | 高 | 撤回按钮 + 扩展比例提示 |
| 证据面板信息过载 | 中 | 中 | 分级展示 + 用户可配置 |
| 定时任务配置复杂 | 高 | 中 | 提供模板 + 可视化配置 |

### 进度风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|---------|
| P0 功能延期 | 中 | 高 | 预留 1 周缓冲时间 |
| P1 需求变更 | 中 | 中 | 先完成 MVP，后续迭代 |
| P2 技术难点 | 中 | 中 | 提前调研 + 原型验证 |
| 资源不足 | 低 | 高 | 优先级排序 + 范围裁剪 |
